Lecture 20: Power BI Import & Model Prep

Get data into Power BI, shape it with Power Query, set types and keys, and prepare a clean model for visualization.

1. Learning Objectives

  • 1 Connect to common sources (Excel, CSV, folders, SQL) via Get Data.
  • 2 Perform essential Power Query steps: promote headers, change types, filter, split, merge.
  • 3 Distinguish Import vs DirectQuery at a high level.
  • 4 Create basic relationships and understand one-to-many cardinality.
  • 5 Apply a checklist before building report pages.

2. Get Data

Power BI Desktop → Home → Get Data. Typical course sources:

  • Excel workbook / CSV / folder of files
  • SQL Server / Azure SQL (when available)
  • Web / OData (APIs)
  • Power BI datasets / Dataflows (enterprise)

Import loads data into the model (fast interactive analysis). DirectQuery leaves data at the source (live but query-bound). Prefer Import for learning and most departmental models.

3. Power Query Essentials

Power Query (Transform Data) is the ELT shaping layer inside Power BI.

StepWhy
Promote headersFirst row becomes column names
Change typeNumbers, dates, text — critical for measures
Remove / rename columnsReduce model size and confusion
Filter rowsDrop null headers, test rows, out-of-scope periods
Split / extractParse codes, dates, hierarchies from text
Merge / appendJoin lookup tables or stack monthly files
Replace errors / fillStabilize refresh
Best practice
Name steps clearly. Prefer shaping in Power Query for structural cleanup; use DAX for business logic and time intelligence (covered in Module 5).

4. Model Prep Basics

  • Mark date tables when you have a calendar dimension
  • Hide technical key columns from Report view if users do not need them
  • Set default summarization (e.g., do not sum Year)
  • Create relationships: fact table (many) → dimension (one) on keys
  • Check relationship direction and cardinality in Model view

5. Pre-Report Checklist

  • ☐ Types correct (date is date, amount is decimal)
  • ☐ No unwanted blank header rows
  • ☐ Keys unique on dimension side
  • ☐ Relationships created and active as intended
  • ☐ Friendly column names for the audience
  • ☐ Sample refresh succeeds without errors

6. Practical

Using a sales CSV + product lookup Excel:

  1. Import both
  2. Promote headers, set types, trim text
  3. Merge product name onto sales on ProductID
  4. Create relationship if kept as separate tables
  5. Verify a simple total sales visual matches Excel sum

7. Knowledge Check

Q1. For a departmental Excel-based sales model, the usual mode is:

A. DirectQuery only
B. Import
C. Live connection to a pie chart
D. No data mode

8. Summary

  • Get Data → shape in Power Query → validate model → then visualize.
  • Correct types and keys prevent silent wrong totals.
  • Import is the default learning path; relationships enforce analysis paths.
