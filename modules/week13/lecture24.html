Lecture 24: Advanced DAX

CALCULATE filter arguments, FILTER, time intelligence, running totals, variables, and iterators — the syllabus advanced layer for real business measures.

1. Learning Objectives

  • 1 Use ALL, REMOVEFILTERS, and values filters inside CALCULATE.
  • 2 Build YTD, prior period, and YoY measures with a proper date table.
  • 3 Create running totals with cumulative patterns.
  • 4 Structure measures with VAR for readability and performance.
  • 5 Apply basic iterators (SUMX) when row-by-row logic is required.

2. CALCULATE Filter Arguments

// Ignore region slicer for a benchmark
Sales All Regions :=
CALCULATE ( [Total Sales], REMOVEFILTERS ( DimGeography[Region] ) )

// Keep only a specific product category
Sales Bikes :=
CALCULATE ( [Total Sales], DimProduct[Category] = "Bikes" )

// Percentage of total
Sales % of All :=
DIVIDE ( [Total Sales], [Sales All Regions] )

Filter arguments replace or extend the existing filter context. Order and interactions matter as models grow.

3. FILTER

FILTER returns a table of rows that satisfy a condition. Often used inside CALCULATE when the condition cannot be expressed as a simple column filter.

High Value Sales :=
CALCULATE (
    [Total Sales],
    FILTER ( Sales, Sales[Amount] > 1000 )
)

4. Time Intelligence (Syllabus)

Requires a marked date table with continuous dates and a relationship to the fact.

Sales YTD :=
TOTALYTD ( [Total Sales], DimDate[Date] )

Sales PY :=
CALCULATE ( [Total Sales], SAMEPERIODLASTYEAR ( DimDate[Date] ) )

Sales YoY % :=
DIVIDE ( [Total Sales] - [Sales PY], [Sales PY] )

Sales MTD :=
TOTALMTD ( [Total Sales], DimDate[Date] )
Requirement
Time intelligence fails silently or incorrectly without a proper date dimension marked as a date table. Build DimDate first (L22).

5. Running Totals

Sales Running Total :=
CALCULATE (
    [Total Sales],
    FILTER (
        ALL ( DimDate[Date] ),
        DimDate[Date] <= MAX ( DimDate[Date] )
    )
)

This cumulative pattern is common for cash flow, enrollment, and inventory movement narratives.

6. VAR and Iterators

// Readable structure with variables
AOV :=
VAR Total = [Total Sales]
VAR Orders = [Order Count]
RETURN DIVIDE ( Total, Orders )

// Iterator: row-by-row then sum
Line Margin :=
SUMX ( Sales, Sales[Amount] - Sales[Cost] )

  4. Rewrite one measure using VAR for clarity.

10. Flashcards

CALCULATE role?
Modify filter context then evaluate expression
YTD pattern?
TOTALYTD ( [Measure], DimDate[Date] )
Running total idea?
CALCULATE measure with FILTER on dates ≤ current date
VAR benefit?
Readability, single evaluation, easier debugging

11. Cheat Sheet

  • CALCULATE ( expr, filters ) · REMOVEFILTERS · ALL
  • Time: TOTALYTD · SAMEPERIODLASTYEAR · marked date table
  • Running total: filter dates ≤ MAX(date) over ALL(dates)
  • VAR ... RETURN · SUMX for row-wise logic

12. Summary

  • CALCULATE + filter arguments unlock % of total and selective filters.
  • Time intelligence needs a proper date table.
  • Running totals and YoY are standard business patterns.
  • VAR and iterators keep advanced measures readable.
