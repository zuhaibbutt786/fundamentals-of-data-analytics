Lecture 24: Advanced DAX

CALCULATE filter arguments, time intelligence, variables, and iterators for real business measures.

1. Learning Objectives

  • 1 Use ALL, REMOVEFILTERS, and values filters inside CALCULATE.
  • 2 Build YTD, prior period, and YoY measures with a proper date table.
  • 3 Structure measures with VAR for readability and performance.
  • 4 Apply basic iterators (SUMX) when row-by-row logic is required.
  • 5 Test measures with simple visual scenarios.

2. CALCULATE Filter Arguments

// Ignore region slicer for a benchmark
Sales All Regions :=
CALCULATE ( [Total Sales], REMOVEFILTERS ( DimGeography[Region] ) )

// Keep only a specific product category
Sales Bikes :=
CALCULATE ( [Total Sales], DimProduct[Category] = "Bikes" )

Filter arguments replace or extend the existing filter context. Order and interactions matter as models grow.

3. Time Intelligence

Requires a marked date table with continuous dates.

Sales YTD :=
TOTALYTD ( [Total Sales], DimDate[Date] )

Sales PY :=
CALCULATE ( [Total Sales], SAMEPERIODLASTYEAR ( DimDate[Date] ) )

Sales YoY % :=
DIVIDE ( [Total Sales] - [Sales PY], [Sales PY] )
Prerequisite
Relationship from fact to DimDate must be active on the correct date key. Mark DimDate as a date table.

4. Variables

Margin % :=
VAR Revenue = [Total Sales]
VAR Cost = [Total Cost]
RETURN
    DIVIDE ( Revenue - Cost, Revenue )

Variables improve readability, avoid double evaluation, and help debugging.

5. Iterators (Intro)

When you need an expression per row before aggregating:

Line Sales :=
SUMX ( Sales, Sales[Qty] * Sales[UnitPrice] )

Prefer simple SUM when a column already holds the line amount.

6. Knowledge Check

Q1. TOTALYTD typically requires:

A. A marked date table and date column
B. Only a text month name
C. No relationships
D. DirectQuery exclusively

7. Summary

  • CALCULATE is the core of filter manipulation.
  • Time intelligence depends on a real date dimension.
  • VAR keeps complex measures clear and efficient.
