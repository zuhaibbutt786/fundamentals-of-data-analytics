Lecture 24: Advanced DAX & Time Intelligence

CALCULATE filter arguments, FILTER, the complete Time Intelligence toolkit (YTD, MTD, YoY, DATEADD…), running totals, and VAR. This is the lecture that turns a basic model into a real analytical dashboard.

1. Learning Objectives

  • 1 Write CALCULATE expressions that add, replace, or remove filters.
  • 2 Use FILTER when you need row-level conditions that CALCULATE’s simple filter arguments cannot express.
  • 3 Build a proper date table and mark it as a date table.
  • 4 Create YTD, MTD, QTD, Prior Year, YoY %, and DATEADD-based measures.
  • 5 Implement running totals and simple VAR-based readable measures.

2. CALCULATE Filter Arguments (Deeper)

// Force a specific category (replaces any existing Category filter)
Sales Bikes :=
CALCULATE ( [Total Sales], DimProduct[Category] = "Bikes" )

// Remove the Region filter so we get a true “all regions” total
Sales All Regions :=
CALCULATE ( [Total Sales], REMOVEFILTERS ( DimGeography[Region] ) )

// Percentage of grand total
Sales % of All :=
DIVIDE ( [Total Sales], [Sales All Regions] )

// Keep current filters but clear the date filter (useful for “all-time” KPIs)
Sales All Time :=
CALCULATE ( [Total Sales], REMOVEFILTERS ( DimDate ) )

Filter arguments inside CALCULATE either add a new filter or replace an existing filter on the same column. REMOVEFILTERS (or ALL) is the explicit way to clear filters.

3. The FILTER Function

When a simple Boolean filter argument is not enough (you need to filter on an expression or on a measure), use FILTER.

// Sales only for products with UnitPrice > 100
High Price Sales :=
CALCULATE (
    [Total Sales],
    FILTER ( DimProduct, DimProduct[UnitPrice] > 100 )
)
Performance note
FILTER iterates a table. Prefer simple filter arguments when possible; use FILTER only when you truly need row-by-row logic.

4. Date Table Requirements (Critical)

Almost every Time Intelligence function requires:

  1. A dedicated DimDate table with one row per day (continuous, no gaps).
  2. A single column of type Date that is marked as the Date table in Power BI (Model view → Mark as date table).
  3. A relationship from the fact table’s date column to DimDate[Date].
How to create DimDate quickly
Use CALENDAR or CALENDARAUTO, then add Year, Month, MonthName, Quarter, DayOfWeek, etc. as calculated columns. Or generate the table in Power Query.

5. Time Intelligence Toolkit

These are the measures every analyst is expected to deliver.

5.1 Year-to-Date / Month-to-Date / Quarter-to-Date

Sales YTD :=
TOTALYTD ( [Total Sales], DimDate[Date] )

Sales MTD :=
TOTALMTD ( [Total Sales], DimDate[Date] )

Sales QTD :=
TOTALQTD ( [Total Sales], DimDate[Date] )

5.2 Prior Year and Year-over-Year

Sales Prior Year :=
CALCULATE ( [Total Sales], SAMEPERIODLASTYEAR ( DimDate[Date] ) )

Sales YoY Growth :=
[Total Sales] - [Sales Prior Year]

Sales YoY % :=
DIVIDE ( [Total Sales] - [Sales Prior Year], [Sales Prior Year] )

5.3 DATEADD — the flexible workhorse

// Same period last month
Sales Prior Month :=
CALCULATE ( [Total Sales], DATEADD ( DimDate[Date], -1, MONTH ) )

// Same period two years ago
Sales Two Years Ago :=
CALCULATE ( [Total Sales], DATEADD ( DimDate[Date], -2, YEAR ) )

// Prior quarter
Sales Prior Quarter :=
CALCULATE ( [Total Sales], DATEADD ( DimDate[Date], -1, QUARTER ) )

5.4 Other useful Time Intelligence functions

FunctionPurpose
SAMEPERIODLASTYEARShift the current date selection back one year
DATEADDShift by any number of years / quarters / months / days
PARALLELPERIODMove to the parallel period of the previous year/quarter/month
PREVIOUSYEAR / PREVIOUSMONTHConvenient wrappers for common shifts
DATESYTD / DATESMTDReturn the set of dates needed for custom YTD/MTD logic

6. Running Totals

Sales Running Total :=
CALCULATE (
    [Total Sales],
    FILTER (
        ALL ( DimDate[Date] ),
        DimDate[Date] <= MAX ( DimDate[Date] )
    )
)

This cumulative pattern is common for cash-flow, enrollment, inventory, and any “progress toward a goal” narrative.

7. VAR — Readable & Efficient Measures

Sales YoY % (readable) :=
VAR CurrentSales = [Total Sales]
VAR PriorSales   = [Sales Prior Year]
VAR Diff         = CurrentSales - PriorSales
RETURN
    DIVIDE ( Diff, PriorSales )

VAR makes complex measures easier to read, debug, and sometimes faster (the variable is evaluated only once).

  4. Create a Sales Prior Month measure with DATEADD.
  5. Build a running total and put it on a line chart with Date on the axis.
  6. (Stretch) Rewrite the YoY % measure using VAR for readability.

11. Flashcards

TOTALYTD purpose?
Returns the year-to-date total of an expression evaluated over a date column.
DATEADD use case?
Shift the current date context by any number of years/quarters/months/days.
Why mark a date table?
Required for most Time Intelligence functions to work correctly.
VAR benefit?
Readability + the expression is evaluated only once (can improve performance).

12. Cheat Sheet — Time Intelligence

  • YTD / MTD / QTD → TOTALYTD / TOTALMTD / TOTALQTD
  • Prior Year → CALCULATE (…, SAMEPERIODLASTYEAR (Date))
  • Any shift → DATEADD (Date, -n, YEAR/QUARTER/MONTH/DAY)
  • Running total → CALCULATE + FILTER (ALL(Date), Date <= MAX(Date))
  • Always mark a continuous DimDate as the date table

13. Summary

  • CALCULATE + filter arguments (and FILTER when needed) give you full control over context.
  • A proper date table is non-negotiable for Time Intelligence.
  • TOTALYTD, SAMEPERIODLASTYEAR, DATEADD and running totals cover the majority of business requests.
  • Use VAR to keep complex measures readable and maintainable.
