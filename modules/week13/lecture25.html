Lecture 25: Performance

Keep models lean and measures efficient so reports stay responsive as data grows.

1. Learning Objectives

  • 1 Reduce model size by removing unused columns and choosing correct types.
  • 2 Prefer star schema and single-direction filters for predictable queries.
  • 3 Write measures that avoid unnecessary iterators and repeated calculations.
  • 4 Use Performance Analyzer habits to find slow visuals.
  • 5 Apply a practical performance checklist before publishing.

2. Model Size

  • Remove columns you never use in visuals or relationships
  • Prefer integers/keys over long text where possible
  • Split date/time if time-of-day is unused
  • Avoid high-cardinality text in fact tables
  • Disable “Auto date/time” when you own a date table

3. Design for Speed

  • Star schema over complex many-to-many webs
  • Single-direction filters unless bidirectional is proven necessary
  • Pre-aggregate only when grain requires it — don’t over-summarize away needed detail
  • Fewer visuals per page; avoid tables with tens of thousands of rows on open

4. Measure Efficiency

  • Use VAR so expensive expressions run once
  • Prefer SUM of a column over SUMX when the line value already exists
  • Avoid CALCULATE inside tight row iterators without need
  • Replace repeated logic with base measures referenced by others

5. Performance Analyzer (Habit)

In Power BI Desktop: View → Performance Analyzer → Start recording → refresh visuals → inspect DAX duration vs visual display time. Fix the slowest measure or the densest visual first.

6. Publish Checklist

  • ☐ Unused columns removed
  • ☐ Date table marked; auto date/time off if appropriate
  • ☐ Relationships reviewed
  • ☐ Heavy pages tested with Performance Analyzer
  • ☐ Aggregations and filters sensible for the audience

7. Knowledge Check

Q1. A practical first step to shrink a slow Import model:

A. Add more bidirectional relationships
B. Convert every measure to a calculated column
C. Remove unused columns
D. Turn on every auto time intelligence option

8. Summary

  • Lean models and simple stars outperform clever complexity.
  • Measure design and visual density matter as much as hardware.
  • Measure → analyze → fix the bottleneck.
