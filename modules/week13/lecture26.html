Lecture 26: Dashboard Project

Integrate modeling, DAX, and visualization into one end-to-end mini dashboard project with clear acceptance criteria.

1. Learning Objectives

  • 1 Scope a business question and KPIs for a sales (or similar) dashboard.
  • 2 Build a star schema from provided tables (fact + dimensions).
  • 3 Implement core measures including a time-intelligence comparison.
  • 4 Design a 1–2 page report following dashboard-thinking principles.
  • 5 Self-assess against a rubric before sharing.

2. Project Brief

Audience: Regional sales manager, weekly review.

Primary questions:

  1. How are we tracking vs last year (revenue)?
  2. Which categories and regions drive the result?
  3. Where should we focus next week?

Required KPIs: Total Sales, YoY %, Order Count, Avg Order Value.

Deliverable: Power BI report (Desktop) with model diagram screenshot + measures list + 1–2 report pages.

3. Build Steps

1. Frame

Write the decision and success criteria (from L4 / L19).

2. Model

Import fact + dimensions; set types; create 1:* relationships; mark date table (L20, L22).

3. Measures

Base measures + YoY / YTD as appropriate (L23, L24). Use VAR where helpful.

4. Pages

Page 1: KPIs + trend + region/category breakdown. Page 2 (optional): exceptions table (L16–L21).

5. Polish & test

Titles as insights, slicers, interactions, Performance Analyzer spot-check (L25).

4. Rubric (Self-Check)

CriterionGood looks like
ModelStar shape, correct cardinality, date table marked
MeasuresNamed measures; YoY or YTD works with date slicer
LayoutKPIs first; clear hierarchy; not overcrowded
ClarityInsight titles; consistent colors; defined filters
CorrectnessTotals match a known Excel/SQL check for a sample filter

5. Stretch Goals

  • Inactive relationship for ship date vs order date + USERELATIONSHIP measure
  • Tooltip page with definitions
  • Bookmark for “This year vs last year” view

6. Summary · End of Module 5

  • Model → measures → visuals is the reliable build order.
  • Acceptance criteria prevent “pretty but wrong” dashboards.
  • You now have the core stack for Module 6 capstone work.
