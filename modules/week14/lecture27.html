Lecture 27: Project Proposal Discussion

Choose a domain dataset, write a clear problem statement, define KPIs, and lock an analytical approach — the syllabus gate before lab work.

1. Learning Objectives

  • 1 Select a domain: Retail, Healthcare, Education, or Financial (or approved equivalent).
  • 2 Write a decision-focused problem statement (not a vague theme).
  • 3 Define 4–7 measurable KPIs tied to that decision.
  • 4 Outline the end-to-end approach (pipeline → clean → EDA → model/viz → dashboard).
  • 5 Submit a one-page proposal that a supervisor can approve in minutes.

2. Domain Choices (Syllabus)

DomainExample decisionExample KPIs
RetailWhere to allocate promo budget next quarterRevenue, margin %, units, return rate by category/region
HealthcareWhere to reduce readmission riskReadmit rate, LOS, cost per case by ward/diagnosis
EducationWhich interventions improve outcomesPass rate, attendance, dropout risk by cohort
FinancialWhere credit risk or cost concentratesDefault rate, NPL, recovery, portfolio exposure

You may use the course sample_accidents.csv as a public-safety / operations domain if approved, or any clean public dataset with enough rows and a clear stakeholder.

3. Problem Statement Template

Format:

“For [stakeholder], we need to decide [decision] by analyzing [data grain], so that [business outcome]. Success means [measurable criteria].”

Weak: “Analyze retail sales.”

Strong: “For the regional sales manager, prioritize categories and stores for the next promo cycle using weekly transaction data, so promo ROI improves. Success: rank top 10 store–category pairs by incremental margin with clear year-over-year context.”

4. KPI Rules

  • Each KPI answers part of the decision
  • Define formula, grain, and time window
  • Include at least one comparison (YoY, target, peer)
  • Avoid vanity metrics that cannot change an action

5. Approach Outline

  1. Data — source, grain, volume, refresh
  2. Quality — expected issues (missing, outliers) and plan (L5–L6)
  3. Features / EDA — key segments and relationships (L8, L11–L14)
  4. Visuals / model — chart types or simple predictive framing
  5. Dashboard — pages, filters, DAX measures (Module 5)
  6. Ethics — privacy, bias, fair reporting (CLO-5)

6. Proposal Deliverable (Submit)

  1. Domain + dataset name / link
  2. Problem statement (5–8 sentences max)
  3. KPI table (name, formula, why it matters)
  4. Approach bullets (pipeline to dashboard)
  5. Risks (data quality, time, scope)

7. Knowledge Check

Q1. A strong proposal must include:

A. Only a chart color palette
B. Problem statement, KPIs, and approach
C. A trained neural net only
D. No dataset choice

8. Summary

  • Pick domain → decide → KPIs → approach → submit.
  • Scope small enough to finish; deep enough to defend in viva.
