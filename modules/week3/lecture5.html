Lecture 5: Data Quality & Profiling

Completeness, consistency, validity, accuracy, missing-data mechanisms (MCAR / MAR / MNAR), deletion vs imputation, and practical profiling + imputation in Python — as specified in the course syllabus.

1. Learning Objectives

By the end of this lecture you will be able to:

  • 1 Define completeness, consistency, validity, and accuracy with operational checks.
  • 2 Profile a dataset using .info(), .describe(), and missing-value counts.
  • 3 Distinguish MCAR, MAR, and MNAR and choose deletion vs imputation accordingly.
  • 4 Apply mean / median / mode imputation and forward / backward fill in Pandas.
  • 5 Document quality issues before any modeling or dashboard work.

2. Motivation — Why Quality Before Analysis

Garbage in, garbage out is not a slogan — it is a project failure mode. A beautiful dashboard built on incomplete, inconsistent, or invalid data will mislead decisions and destroy trust.

Profiling is the first technical step after acquisition (L3) and framing (L4). It answers: What is here? What is missing? What is impossible? What conflicts? Only then do you decide what to fix, drop, or escalate.

💡 Key Insight
Spend 20–30% of early project time on quality. It is cheaper than explaining wrong insights later in the viva or to a stakeholder.

3. Real-World Story

The Dashboard That “Proved” Zero Accidents

A transport analytics team published a weekly safety dashboard showing zero serious accidents in one district. Leadership celebrated. A week later, a journalist reported two fatal crashes in the same district. The cause: the district code in the source system had changed, and the join to the geography table silently dropped those rows. Completeness looked fine on the fact table; validity of the key failed.

Profiling foreign keys and row counts against expected volumes would have caught the break before the dashboard went live.

4. Problem Statement

Given a newly acquired dataset, how do you:

  • Measure completeness, consistency, validity, and accuracy?
  • Detect and describe missingness patterns?
  • Decide when to delete vs impute?
  • Apply baseline imputation methods correctly in Python?
  • Report quality risks clearly to stakeholders?

5. Four Core Quality Dimensions

DimensionMeaningQuick check
CompletenessRequired fields are present% null / blank per column; expected row count
ConsistencySame entity, same values across sources or rowsDuplicate keys; conflicting totals; unit mismatches
ValidityValues obey rules (type, range, format, domain)Age < 0; email without @; invalid codes
AccuracyValues match reality / source of truthSample audit vs source system; known benchmarks

Profiling answers these four questions systematically before any transformation or model.

6. Profiling Techniques (Syllabus Practical)

Use these on every new extract. The course dataset sample_accidents.csv is ideal for practice.

import pandas as pd

df = pd.read_csv("../../datasets/sample_accidents.csv")

# Structure and completeness
df.info()                          # types, non-null counts
df.shape                           # rows × columns

# Distribution summary
df.describe(include="all")         # numeric + categorical summary

# Missingness
df.isna().sum()                    # missing count per column
df.isna().mean().sort_values(ascending=False)  # missing rate

# Duplicates and keys
df.duplicated().sum()              # exact duplicate rows
df["accident_id"].is_unique        # key integrity (if column exists)

# Value ranges and categories
df["severity"].value_counts(dropna=False)
df.select_dtypes("number").min()
df.select_dtypes("number").max()
Analyst habit
After every load, print shape, dtypes, missing rates, and a few value_counts. Quality issues surface here — not three hours later in a chart.

8. Types of Missing Data (MCAR / MAR / MNAR)

TypeDefinitionImplication
MCARMissing Completely At Random — missingness unrelated to any variableSimple deletion less biased
MARMissing At Random — missingness depends on observed variablesImpute using observed predictors
MNARMissing Not At Random — missingness depends on the unobserved value itselfHardest; need domain model or sensitivity analysis
Practice tip
You rarely prove MCAR. Treat “random” claims carefully; always inspect missingness by group (region, severity, date).

Easy examples

  • MCAR: A sensor randomly drops packets — missing temperature is unrelated to the true temperature or other fields.
  • MAR: Older patients are less likely to report income; age is observed, so missingness depends on an observed variable.
  • MNAR: People with very high income refuse to report income — missingness depends on the missing value itself.

9. Deletion vs Imputation

  • Listwise deletion — drop rows with any missing field (simple; loses data; bias if not MCAR).
  • Column drop — if a field is mostly empty and low value for the decision.
  • Mean / median / mode — fast baseline; median preferred for skewed numerics; mode for categoricals.
  • Forward fill / backward fill — time-ordered series (use with care at series edges).
  • Model-based — later stage (KNN, regression); document assumptions.

Python — Syllabus methods

# Mean / median / mode imputation
df["casualties"] = df["casualties"].fillna(df["casualties"].median())
df["weather"] = df["weather"].fillna(df["weather"].mode().iloc[0])

# Time-aware fill (after sorting by date)
df = df.sort_values("date")
df["speed_limit"] = df["speed_limit"].ffill().bfill()

# Optional: flag that a value was imputed (good practice)
df["casualties_imputed"] = df["casualties"].isna()  # before fill
df["casualties"] = df["casualties"].fillna(df["casualties"].median())
Industry tip
Always record whether a value was imputed. Downstream models and audits need to know what was original vs filled.

10. Industry Examples

Healthcare

Lab results often missing for healthier patients (MAR). Blood pressure missing because it was too high to measure easily can be MNAR. Never impute clinical outcomes without clinical review.

Banking

Income and employment fields are frequently incomplete. MNAR risk is high for high-income or unemployed applicants. Use domain rules and document every fill.

Retail / E-commerce

Product attributes (color, size) missing more for older catalog items (MAR by launch date). Sales quantity zero vs missing means different things — validity rules matter.

Transport (course dataset)

Accident severity, weather, and casualties may have systematic gaps by region or reporting period. Profile by group before global median fill.

15. Cheat Sheet

  • Profile first: shape · dtypes · missing rates · duplicates · key uniqueness · value ranges
  • Dimensions: Completeness · Consistency · Validity · Accuracy
  • Missingness: MCAR (random) · MAR (observed) · MNAR (value itself)
  • Impute: median (skewed numeric) · mode (categorical) · ffill/bfill (time series)
  • Always: document what was dropped or filled; flag imputed rows when possible

16. Common Mistakes & Best Practices

Avoid
  • Mean-imputing highly skewed or bounded variables without thought
  • Silent listwise deletion of 30%+ of rows
  • Global fill without checking missingness by group
  • Treating “0” and “missing” as the same without a rule
  • Skipping key uniqueness and row-count checks
Prefer
  • Profile before any transform or model
  • Inspect missingness by segment (region, date, severity)
  • Median/mode as baseline; document assumptions
  • Keep a raw bronze copy; log cleaning steps
  • Report quality risks in plain language to stakeholders

17. Summary

  • Profile first: completeness, consistency, validity, accuracy.
  • Missingness type (MCAR / MAR / MNAR) guides deletion vs imputation.
  • Median, mode, and ffill/bfill are the syllabus baseline tools in Python.
  • Document every quality decision — it protects you in review and in the viva.
