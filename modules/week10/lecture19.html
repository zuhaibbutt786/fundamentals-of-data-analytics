Lecture 19: Dashboard Thinking

Design dashboards for decisions: audience, layout hierarchy, KPI selection, filters, and interaction patterns that reduce noise.

1. Learning Objectives

  • 1 Define dashboard purpose and primary audience before choosing visuals.
  • 2 Layout a page with Z/F scanning and KPI → detail flow.
  • 3 Limit KPIs and filters to what the decision requires.
  • 4 Plan cross-filtering and drill paths without trapping users.
  • 5 Write acceptance criteria for a “useful” dashboard.

2. Purpose First

Answer before building:

  • Who is the primary user (role)?
  • What decision do they make with this page?
  • How often do they open it (real-time, daily, weekly)?
  • What is the one question the homepage must answer in 5 seconds?
Types
Strategic (high-level trends) · Analytical (explore drivers) · Operational (monitor live process)

3. Layout Hierarchy

  • Top-left / top band: most important KPIs and status
  • Center: main trend or comparison that explains the KPIs
  • Right / bottom: breakdowns, tables, secondary detail
  • Filters: consistent place (top or left); default to “most useful” not “all time”

One page ≈ one job. Split into multiple pages when audiences or decisions diverge.

Website analytics example
Course site dashboard: KPI strip (visits, quiz completion, avg time) → main line (weekly engagement) → right bar (lectures with lowest scores) → optional detail table. Same pattern as sales ops or support ops dashboards.

4. KPIs & Filters

DoDon’t
3–7 primary KPIs with clear definitions20 KPI cards with no hierarchy
Show target / prior period / statusOrphan numbers with no comparison
Filters that match real decisionsEvery column as a slicer
Reset / clear filters controlHidden filter state that confuses users

5. Interaction Patterns

  • Cross-filter: clicking a bar filters related charts
  • Drill-through: from summary to transaction detail
  • Tooltips: definitions and extra context without clutter
  • Bookmarks / tabs: alternate views for different roles

Always provide a way back to the default view.

6. Practical — Wireframe a Sales Ops Dashboard

Audience: regional sales managers, weekly review.

Sketch (list zones):

  1. Top KPIs (3–5) with vs target and vs last week
  2. Main trend chart
  3. Breakdown (region or product)
  4. Exception table (deals at risk)
  5. Filters needed

7. Knowledge Check

Q1. First step when designing a dashboard?

A. Pick the most colorful visuals
B. Import every table available
C. Clarify audience and decision
D. Maximize number of slicers

8. Summary

  • Dashboards exist for decisions — design from purpose and audience.
  • Layout: KPIs → explanation → detail; one page, one job.
  • Few well-defined KPIs beat many vague metrics.
  • Interactions should clarify, not confuse; always allow reset.
