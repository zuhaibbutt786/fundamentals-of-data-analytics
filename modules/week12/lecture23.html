Lecture 23: DAX Basics

Calculated columns vs measures, filter context, CALCULATE, and the core aggregation patterns every Power BI analyst must master. Fully aligned with CS-399 and the Power BI / DAX course materials.

1. Learning Objectives

  • 1 Explain the difference between a calculated column and a measure and choose correctly.
  • 2 Describe filter context and row context in plain language.
  • 3 Write basic aggregation measures (SUM, COUNT, AVERAGE, DISTINCTCOUNT).
  • 4 Use CALCULATE to modify filter context (the most important function in DAX).
  • 5 Build percentage-of-total and simple ratio measures.

2. Motivation

Power BI visuals are only as good as the measures behind them. Without solid DAX you are limited to the raw columns that came from the source. With DAX you create business KPIs, ratios, comparisons, and time-intelligence calculations that stakeholders actually care about.

💡 Key Insight
CALCULATE is the single most important function in DAX. Almost every advanced pattern eventually uses it. Master filter context + CALCULATE and the rest of DAX becomes far easier.

3. Calculated Column vs Measure

Calculated ColumnMeasure
When evaluatedAt data refresh (row by row)At query time (depends on filter context)
StorageStored in the model (uses memory)Not stored — calculated on the fly
Use whenYou need a value per row that can be used for filtering, grouping or relationshipsYou need an aggregation or KPI that responds to slicers and visual filters
ExampleMargin = Sales[Revenue] - Sales[Cost]Total Sales = SUM(Sales[Revenue])
Rule of thumb
Prefer measures whenever possible. Calculated columns increase model size and are evaluated only at refresh. Measures stay flexible and respond to every filter the user applies.

4. Core Aggregation Patterns

Total Sales :=
SUM ( Sales[Revenue] )

Order Count :=
COUNTROWS ( Sales )

Distinct Customers :=
DISTINCTCOUNT ( Sales[CustomerID] )

Average Order Value :=
DIVIDE ( [Total Sales], [Order Count] )

// Safe division — never returns Infinity
Profit Margin % :=
DIVIDE ( [Total Profit], [Total Sales] )

Always prefer DIVIDE over the / operator when the denominator might be zero.

5. Filter Context (Easy Explanation)

Filter context is the set of filters that are currently applied to the data when a measure is evaluated. Filters come from:

  • Slicers on the report page
  • Rows / columns / legends of a visual
  • Filters on the visual, page, or report
  • Explicit filters you pass inside CALCULATE

A measure sees only the rows that survive all of those filters. That is why the same measure can show different numbers in different cells of a matrix.

6. First CALCULATE Patterns

CALCULATE evaluates an expression under a modified filter context. It is the engine that lets you create comparisons, ratios, and “all” benchmarks.

// Sales for Bikes only
Sales Bikes :=
CALCULATE ( [Total Sales], DimProduct[Category] = "Bikes" )

// Ignore the Region slicer — create an “all regions” benchmark
Sales All Regions :=
CALCULATE ( [Total Sales], REMOVEFILTERS ( DimGeography[Region] ) )

// Percentage of all regions
Sales % of All Regions :=
DIVIDE ( [Total Sales], [Sales All Regions] )

// Keep the current filters but force a specific year
Sales 2024 :=
CALCULATE ( [Total Sales], DimDate[Year] = 2024 )
Mental model
CALCULATE first applies the new filters (or removes existing ones), then evaluates the measure inside that new filter context.

10. Flashcards

Column vs Measure?
Column = stored at refresh, row context. Measure = calculated at query time, filter context.
What does CALCULATE do?
Evaluates an expression under a modified filter context.
Safe division?
Always use DIVIDE(numerator, denominator) instead of /
REMOVEFILTERS purpose?
Clears filters on the specified columns/tables so you can create “all” benchmarks.

11. Cheat Sheet

  • Prefer measures over calculated columns when possible
  • SUM / COUNTROWS / DISTINCTCOUNT / DIVIDE — everyday aggregation toolkit
  • CALCULATE(expression, filter1, filter2…) — modify filter context
  • REMOVEFILTERS / ALL — create “grand total” style benchmarks
  • Filter context comes from slicers, visuals, and CALCULATE arguments

12. Summary

  • Measures respond to filter context; calculated columns are static after refresh.
  • CALCULATE is the core of almost every non-trivial DAX pattern.
  • Master the basic aggregations and simple CALCULATE filters before moving to time intelligence.
