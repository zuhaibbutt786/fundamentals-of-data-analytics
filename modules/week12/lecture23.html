Lecture 23: DAX Basics

Measures vs calculated columns, core aggregation functions (SUM, COUNT, AVERAGE), filter context, and your first CALCULATE patterns — syllabus core for Module 5.

1. Learning Objectives

  • 1 Choose calculated column vs measure for a given need.
  • 2 Write measures with SUM, COUNTROWS, DISTINCTCOUNT, AVERAGE.
  • 3 Explain filter context in plain language.
  • 4 Use CALCULATE to modify filters (simple cases).
  • 5 Avoid common beginner mistakes (summing wrong columns, ignoring context).

2. Motivation

Excel-style thinking (“put a formula in every cell”) does not scale in Power BI. DAX separates row-level attributes (columns) from aggregations that respond to slicers (measures). Mastering that split is the foundation of every dashboard KPI.

3. Calculated Column vs Measure

Calculated columnMeasure
EvaluatedAt refresh, row by rowAt query time, in filter context
StoredIn the model (uses memory)Not stored as values
Use whenRow-level attributes, slicing by new categoriesAggregations, ratios, time intelligence
ExampleFullName = First & " " & LastTotal Sales = SUM(Sales[Amount])
Rule of thumb
Prefer measures for anything that aggregates. Prefer columns when you need a static label per row.

4. Core Aggregation Patterns (Syllabus)

Total Sales := SUM ( Sales[Amount] )

Order Count := COUNTROWS ( Sales )

Customer Count := DISTINCTCOUNT ( Sales[CustomerKey] )

Avg Order Value := DIVIDE ( [Total Sales], [Order Count] )

Average Amount := AVERAGE ( Sales[Amount] )

Use DIVIDE instead of / to handle divide-by-zero safely. Prefer COUNTROWS on a table over counting a column when you mean “number of rows in context.”

5. Filter Context (Easy Explanation)

When a measure evaluates, Power BI applies filters from slicers, rows, columns, and visuals. That set of filters is the filter context. The same measure formula returns different numbers in different cells of a matrix because the context changes.

6. First CALCULATE Patterns

CALCULATE evaluates an expression under a modified filter context — the gateway to almost all advanced DAX.

// Sales for a specific category
Sales Bikes :=
CALCULATE ( [Total Sales], DimProduct[Category] = "Bikes" )

// Sales ignoring the region slicer (benchmark)
Sales All Regions :=
CALCULATE ( [Total Sales], REMOVEFILTERS ( DimGeography[Region] ) )

7. Hands-on Lab

  1. Create measures: Total Sales, Order Count, Average Order Value (using DIVIDE).
  2. Put them in a matrix with a date or product hierarchy; change slicers and observe context.
  3. Add one CALCULATE measure that filters to a single category.
  4. Write one sentence explaining why Total Sales changes when you select a year.

8. Interview & Viva Questions

  • When do you use a calculated column instead of a measure?
  • What is filter context? Give an example from a matrix visual.
  • Why prefer DIVIDE over the / operator?
  • What does CALCULATE do in one sentence?

10. Flashcards

Column vs Measure?
Column = row-level at refresh; Measure = aggregation at query time
Core aggregates?
SUM, COUNTROWS, DISTINCTCOUNT, AVERAGE, DIVIDE
Filter context?
Filters from slicers + visual axes that shape measure results
CALCULATE role?
Evaluate expression under modified filter context

11. Cheat Sheet

  • Measures for aggregations; columns for row labels
  • SUM · COUNTROWS · DISTINCTCOUNT · AVERAGE · DIVIDE
  • Filter context = slicers + coordinates of the visual cell
  • CALCULATE ( expr, filters... ) modifies context

12. Summary

  • Choose column vs measure deliberately.
  • Master SUM, COUNT, AVERAGE patterns and DIVIDE for ratios.
  • Understand filter context before advanced time intelligence.
  • Use simple CALCULATE filters as the bridge to Lecture 24.
