Lecture 8: Feature Engineering Basics

Create derived columns, aggregation features, date-time parts, and bins that answer real business questions — not just inflate the column count. Fully aligned with CS-399 and the Feature Engineering course materials.

1. Learning Objectives

  • 1 Create derived columns (ratios, differences, flags, interactions) from existing fields.
  • 2 Build aggregation features at a coarser grain and join them back when needed.
  • 3 Extract useful date-time components (year, month, day-of-week, lag, rolling).
  • 4 Bin continuous variables into meaningful categories for analysis or modelling.
  • 5 Design features that directly support a business question instead of “feature spam”.

2. Motivation — Why Feature Engineering Wins

Raw columns are rarely the most informative representation. A simple ratio (revenue / quantity), a flag (is_weekend), or a lagged value often gives more lift than a complex algorithm on the original data. Good feature engineering is the highest-ROI skill an analyst can develop.

💡 Key Insight
Feature engineering is applied domain knowledge. The best features come from understanding the business, not from blindly applying every possible transform.

3. Real-World Story

The Churn Model That Finally Worked

A telecom team had dozens of raw usage columns (minutes, SMS, data). Predictive power stayed mediocre until an analyst engineered three features:

  • avg_daily_data_last_7d / avg_daily_data_last_30d (usage drop)
  • days_since_last_recharge
  • is_night_heavy_user (binary flag from hour-of-day patterns)

These three domain-inspired features outperformed the previous 40-column model and became the core of the production churn dashboard.

4. Derived Columns

New columns created by arithmetic or logical combinations of existing ones.

Ratiorevenue = qty × unit_priceTotal value of the line
Margin(revenue − cost) / revenueProfitability

Differenceplanned − actualVariance / delay

import pandas as pd
import numpy as np

df = pd.read_csv("../../datasets/sample_sales.csv")

# Derived columns
df["revenue"] = df["Quantity"] * df["UnitPrice"]
df["discounted_revenue"] = df["revenue"] * (1 - df["Discount"])
df["high_value"] = (df["revenue"] > df["revenue"].median()).astype(int)
df["is_electronics"] = (df["Category"] == "Electronics").astype(int)

print(df[["Product","Quantity","UnitPrice","revenue","discounted_revenue"]].head())

5. Aggregation Features

Sometimes the interesting signal lives at a coarser grain (customer, region, product, month). Aggregate first, then join the summary back to the original table if you still need row-level detail.

# Region-level aggregates
region_stats = df.groupby("Region").agg(
    region_orders=("OrderID", "count"),
    region_revenue=("revenue", "sum"),
    region_avg_discount=("Discount", "mean")
).reset_index()

df = df.merge(region_stats, on="Region", how="left")

# Now each row knows how its region performs overall
print(df[["Region","revenue","region_revenue","region_orders"]].head())
Leakage warning
When building aggregates for predictive models, compute them only on past data (or inside cross-validation folds). Aggregating on the whole dataset including the target period leaks future information.

6. Date-Time Feature Extraction

Dates hide rich structure. Extracting calendar parts and time-based lags is one of the highest-value engineering steps for any temporal dataset.

  • Calendar parts: year, month, day, day-of-week, quarter, is_weekend, is_month_end
  • Lags: value from 1 / 7 / 30 periods ago
  • Rolling windows: mean / sum / std over the last N periods
  • Time since event: days since last purchase / last claim / last login
df["OrderDate"] = pd.to_datetime(df["OrderDate"])

df["year"]        = df["OrderDate"].dt.year
df["month"]       = df["OrderDate"].dt.month
df["day_of_week"] = df["OrderDate"].dt.dayofweek          # 0=Monday
df["is_weekend"]  = df["day_of_week"].isin([5,6]).astype(int)
df["quarter"]     = df["OrderDate"].dt.quarter

# Example lag (requires sorted data)
df = df.sort_values("OrderDate")
df["prev_revenue"] = df.groupby("CustomerID")["revenue"].shift(1)

7. Binning Continuous Variables

Turning a continuous variable into ordered categories can make patterns easier to communicate and sometimes improves model stability.

MethodWhen to useExample
Equal-widthUniform ranges desiredAge 0–20, 20–40, 40–60…
Equal-frequency (quantile)Balanced group sizespd.qcut(…, q=4)
Domain / business binsMeaningful thresholds existAge <18, 18–25, 26–40, 41–65, 65+
 
# Business-driven bins for UnitPrice
df["price_band"] = pd.cut(
    df["UnitPrice"],
    bins=[0, 50, 200, 500, np.inf],
    labels=["Budget", "Mid", "Premium", "Luxury"]
)

# Quantile bins
df["revenue_quartile"] = pd.qcut(df["revenue"], q=4, labels=["Q1","Q2","Q3","Q4"])

8. Feature Engineering Principles

  • Start from the question — every feature should help answer a specific business or analytical question.
  • Prefer interpretable features — especially for dashboards and stakeholder communication.
  • Watch leakage — never use information that would not be available at prediction time.
  • Document the logic — future you (or a colleague) must understand why the column exists.
  • Validate impact — compare model / insight quality before and after the new features.

9. Complete Python Lab

Use sample_sales.csv (and optionally Titanic or Electric Production from the datasets README).

import pandas as pd
import numpy as np

df = pd.read_csv("../../datasets/sample_sales.csv")
df["OrderDate"] = pd.to_datetime(df["OrderDate"])

# 1. Derived
df["revenue"] = df["Quantity"] * df["UnitPrice"]
df["discounted_revenue"] = df["revenue"] * (1 - df["Discount"])
df["high_value_order"] = (df["revenue"] > 200).astype(int)

# 2. Aggregation
cat_stats = df.groupby("Category").agg(
    cat_avg_price=("UnitPrice", "mean"),
    cat_total_qty=("Quantity", "sum")
).reset_index()
df = df.merge(cat_stats, on="Category", how="left")

# 3. Date-time
df["month"] = df["OrderDate"].dt.month
df["day_of_week"] = df["OrderDate"].dt.day_name()
df["is_weekend"] = df["OrderDate"].dt.dayofweek.isin([5,6]).astype(int)

# 4. Binning
df["price_band"] = pd.cut(df["UnitPrice"], bins=[0,50,200,500,np.inf],
                          labels=["Budget","Mid","Premium","Luxury"])

print(df[["Product","revenue","price_band","cat_avg_price","is_weekend"]].head(8))
print("\nValue counts of price_band:\n", df["price_band"].value_counts())

14. Cheat Sheet

  • Derived: ratios, margins, flags, differences, interactions
  • Aggregation: group-by → join back (watch leakage)
  • Date-time: calendar parts + lags + rolling windows
  • Binning: equal-width · quantile · business thresholds
  • Rule: every feature must serve a clear question

15. Summary

  • Feature engineering turns raw columns into signals that answer business questions.
  • Derived columns, aggregates, date parts and bins are the four everyday tools.
  • Always guard against leakage and document the logic behind each new feature.
  • Validate that the new features actually improve insight or model quality.
